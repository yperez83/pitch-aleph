Step 3: 3. The Predictive Engine
Narrative: As live event data streams in, PitchAleph calculates real-time win probability. We use dynamic SQL window functions to measure rolling Expected Threat (xT) spikes against the market's lagging live odds.

Step 4: 4. Execution Window
Narrative: The 25% Test: We blindfolded the model. At exactly 22.5 minutes, PitchAleph detected an extreme territorial imbalance. While Vegas implied a 40% probability, PitchAleph calculated 65%, executing a +EV buy order right before Argentina scored.

Test 04: Volatility & Hedging (NED vs ARG 2022 QF)
------------------------------------------------------------

Title: Volatility & Hedging
Subtitle: Knowing when the predictive models break down.

Step 1: 1. The Baseline State
Narrative: For 75 minutes, the Netherlands played a structured, possession-based game. PitchAleph's standard spatial models were accurately predicting match flow and keeping our Argentina position secure.

Step 2: 2. Tactical Rupture
Narrative: Trailing 2-0, the Netherlands completely abandoned 'Total Football'. They brought on 6-foot-6 striker Wout Weghorst and began launching direct long balls from deep in their own half. The structured game state evaporated.

Step 3: 3. Measuring Match Chaos
Narrative: PitchAleph flagged a 'Regime Change.' Pass completion rates plummeted, aerial duels skyrocketed, and variance went off the charts. The game devolved into raw physical chaos, meaning all historical predictive probabilities were completely voided.

Step 4: 4. Dynamic Hedging
Narrative: A core quant principle: Do not trade in chaotic states you cannot model. Sensing extreme volatility, PitchAleph executed an automated hedge. Instead of risking the original Argentina position in a coin-flip scenario, the engine cashed out to lock in a guaranteed profit. Minutes later, the Netherlands scored a miraculous equalizer. The public lost; PitchAleph profited.

API Name: Pitch Aleph Quantitative Betting Engine API
Version: 1.0.0
Interactive Documentation URL: /api/docs (Swagger UI)
OpenAPI 3.0.3 Specification: /api/openapi.json
Base URL: /api/v1
Description: Public RESTful API for Pitch Aleph. Exposes programmatic access to the Data Vault matches, 1,000-Match Backtest ledger, and the mathematical Bet Simulator engine. Note: This environment operates as an interactive sandbox/demo; create, update, and delete mutations persist in-memory for the active runtime instance.

Authentication Schemes:
  • API Key Authentication: Header 'x-api-key: <your_key>' (e.g. aleph_demo_key_2026)
  • Bearer Token Authentication: Header 'Authorization: Bearer <your_key>'

Standard HTTP Response Codes:
  • 200 OK — Successful retrieval or calculation
  • 201 Created — Resource successfully registered
  • 400 Bad Request — Malformed request syntax or validation error
  • 401 Unauthorized — Missing or invalid API key
  • 404 Not Found — Resource ID does not exist
  • 500 Internal Server Error — Server execution failure

Core Endpoints:
  1. GET /api/v1/matches
     Summary: List all Data Vault matches
     Description: Returns all analyzed match scenarios with optional status (ALL, PASS, FAIL) and text search filtering.

  2. POST /api/v1/matches
     Summary: Register a new match scenario
     Description: Creates a new match backtest scenario in the Data Vault.

  3. GET /api/v1/matches/{id}
     Summary: Get match by ID
     Description: Returns granular quantitative details and tactical breakdown steps for a specific match.

  4. PUT /api/v1/matches/{id}
     Summary: Update match scenario
     Description: Updates properties of an existing match scenario.

  5. DELETE /api/v1/matches/{id}
     Summary: Delete match scenario
     Description: Removes a match scenario from the active Data Vault ledger.

  6. GET /api/v1/backtest
     Summary: Get backtest P&L ledger
     Description: Returns the trade-by-trade cumulative bankroll performance ledger across 522 executions.

  7. POST /api/v1/simulate
     Summary: Run mathematical bet simulator
     Description: Evaluates a user base stake against Pitch Aleph quantitative expectation models and returns comparative expected outcome vs public bettor outcome.
